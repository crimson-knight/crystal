# The Mica encoding engine (the default)

`String#encode`, `String.new(bytes, encoding)`, `String.encode` and
`IO#set_encoding` run on [Mica](https://github.com/amberframework/mica)'s
implementation of the [WHATWG Encoding Standard](https://encoding.spec.whatwg.org/).
Mica is written in Crystal, and a program built this way links no iconv:

```console
$ crystal build app.cr
$ otool -L app      # or ldd: no libiconv
$ nm -mu app | grep -c iconv
0
```

## Choosing the engine

| Build | Encoding engine |
|---|---|
| `crystal build app.cr` | Mica |
| `crystal build -Duse_libiconv app.cr` | GNU libiconv (`libiconv_*` symbols, links `libiconv`) |
| `crystal build -Duse_iconv app.cr` | the platform's iconv (glibc's `iconv_*` on Linux, `libiconv` on macOS) |
| `crystal build -Dwithout_iconv app.cr` | none: the encoding methods are absent, as before |

The regex (`-Duse_pcre2`, `doc/regex_mica.md`) and YAML (`-Duse_libyaml`,
`doc/yaml_mica.md`) engines have their own opt-outs; the three are
independent.

## Encodings

Mica knows every encoding of the Encoding Standard (UTF-8, UTF-16BE/LE,
the 28 single-byte encodings, gb18030, GBK, Big5, EUC-JP, ISO-2022-JP,
Shift_JIS, EUC-KR) plus the iconv names programs commonly use: exact
ISO-8859-1, US-ASCII, UTF-16 and UTF-32 with a byte order mark,
UTF-32BE/LE, UCS-2, UCS-2BE/LE and BIG5-HKSCS.

Names are read with their iconv meaning, so code written for iconv keeps
its results: `ISO-8859-1` is exact Latin-1 (byte 0x80 is U+0080, not the
euro sign a browser would read), `US-ASCII` rejects bytes over 0x7F,
`UTF-16` and `UTF-32` write a byte order mark and then little-endian
units, and `UTF-16`, `UTF-32` and `UCS-2` read little-endian when no mark
says otherwise (glibc's behavior; macOS libiconv uses big-endian there),
`UCS-2` refuses characters outside the Basic Multilingual Plane, and `BIG5-HKSCS` decodes
and writes the four composed pairs (0x8862, 0x8864, 0x88A3, 0x88A5).

Any other name raises:

```text
Invalid encoding: UTF-7 (the built-in engine knows the WHATWG Encoding Standard's encodings plus UTF-16, UTF-32, UCS-2, ISO-8859-1, US-ASCII and BIG5-HKSCS; build with -Duse_libiconv or -Duse_iconv for others)
```

Build with `-Duse_iconv` for UTF-7, the EBCDIC code pages, ISO-2022-CN/KR
and the other encodings only iconv has.

## Errors

`invalid: nil` (the default) raises `ArgumentError` with iconv's messages,
`"Invalid multibyte sequence"` or `"Incomplete multibyte sequence"`;
`invalid: :skip` drops what does not convert. A decoder skips each maximal
ill-formed subpart (Unicode chapter 3, Table 3-8), which is where iconv
implementations differ among themselves; see Mica's `docs/encoding.md`,
"Differences from iconv".

Each `IO` write is converted as a whole: a sequence left open at the end
of a write is incomplete, and shift states (ISO-2022-JP, a BIG5-HKSCS Ê
or ê waiting for a combining mark) are closed at the end of the write.

## How Mica reaches the standard library

- `src/crystal/mica/` is a copy of `Mica::Encoding` and the two
  `Mica::Core` files it uses, generated by `scripts/vendor_mica_encoding.cr`
  from a pinned commit. The script refuses a checkout whose commit or tree
  hash differs from the pins and records the sha256 of every vendored file
  in `src/crystal/mica/VENDORED.md`. Nothing there is edited by hand.
- The copy lives in `Crystal::Mica`, apart from the top-level `Mica` an
  application may require as a shard. (`String` requires the engine
  before `IO` is defined, so the regex and YAML engines' `Regex::Mica` /
  `YAML::Mica` pattern does not fit here.)
- `src/crystal/mica_encoding.cr` adapts it to the standard library's
  methods and messages. `src/string.cr` and `src/io/encoding.cr` pick
  Mica or `Crystal::Iconv` at compile time; a program built with
  `-Duse_iconv` or `-Duse_libiconv` compiles nothing in `src/crystal/mica/`.
- The engine's tables are the Encoding Standard's index files compiled to
  read-only data. Reverse lookups for encoders are built on the first
  `encode` to each encoding and kept for the life of the process. Nothing
  in the engine allocates a `Hash` while constants initialize (they do so
  before `Crystal::Hasher` is seeded).

## Evidence

Mica's `docs/encoding.md` holds the conformance and speed evidence: the
web-platform-tests `encoding/` suite (11,881 of 11,881 subtests), index
round trips, a differential against the WPT reference codecs and ICU, a
differential against iconv with every difference explained, a fuzz
campaign, and throughput against libiconv. `spec/std/string_spec.cr` and
`spec/std/io/io_spec.cr` pass on both engines.
