# The Mica DEFLATE engine (the default)

`Compress::Deflate`, `Compress::Gzip`, `Compress::Zlib` and `Compress::Zip`,
and the `Digest::CRC32` and `Digest::Adler32` checksums, run on
[Mica](https://github.com/amberframework/mica)'s DEFLATE, written in
Crystal. A program built this way links no libz, and so does everything
built on them: `HTTP::Client` reading gzip and deflate responses and
`HTTP::CompressHandler` compressing responses.

```console
$ crystal build app.cr
$ otool -L app      # or ldd: no libz
$ nm -u app | grep -cE '_(deflate|inflate|crc32|adler32|zlibVersion)'
0
```

## Choosing the engine

| Build | DEFLATE engine |
|---|---|
| `crystal build app.cr` | Mica |
| `crystal build -Duse_libz app.cr` | zlib (links `libz`) |
| `crystal build -Dwithout_zlib app.cr` | none: `HTTP` neither compresses nor decompresses, as before |

The regex (`-Duse_pcre2`), YAML (`-Duse_libyaml`) and encoding
(`-Duse_libiconv`, `-Duse_iconv`) engines have their own opt-outs; the
four are independent.

## What stays the same

- The public API: every class, constructor and method keeps its
  signature. Levels run from `NO_COMPRESSION` (0) to `BEST_COMPRESSION`
  (9); `DEFAULT_COMPRESSION` (-1) is level 6, as in zlib.
- Formats on the wire: streams Mica writes are standard DEFLATE, zlib and
  gzip, and zlib reads them; Mica reads what zlib writes.
- `Writer#flush` ends the output on a byte boundary so a reader can decode
  everything written before it (zlib's `Z_SYNC_FLUSH`).
- A reader takes from its underlying IO only the bytes of the DEFLATE
  stream, through `IO#peek` when the IO has it and a byte at a time
  otherwise, as with zlib. The gzip and zlib trailers, and the next entry
  of a zip file read with `Compress::Zip::Reader`, are still there to read.
- No limits beyond DEFLATE's own: any output size, any number of gzip
  members.

## What differs

- Compressed bytes: Mica's encoder makes different (equally valid) choices
  from zlib's, so the same input and level can compress to different
  bytes and sizes.
- `Compress::Deflate::Strategy` applies to zlib only; Mica has one
  strategy and ignores it.
- Errors: a malformed or truncated stream raises
  `Compress::Deflate::Error` as before, with Mica's message after
  `deflate: ` (zlib's `buffer error` for a truncated stream reads
  `Input ends inside ...`). The Mica error is the exception's `cause`.
- A `dict` given to `Compress::Deflate::Reader` or `Writer` (and through
  them to `Compress::Zlib`) is used as the stream's preset dictionary, as
  RFC 1950 describes; the zlib engine records it but does not apply it.

## How Mica reaches the standard library

- `src/crystal/mica/` holds a copy of `Mica::Deflate`, `Mica::Zlib`,
  `Mica::Gzip` and the `Mica::Core` files they use, beside Mica's encoding
  engine, generated by `scripts/vendor_crystal_mica.cr` from a pinned
  commit. The script refuses a checkout whose commit or tree hash differs
  from the pins and records the sha256 of every vendored file in
  `src/crystal/mica/VENDORED.md`. Nothing there is edited by hand.
- `src/compress/deflate/mica/` adapts Mica's reader and writer to
  `Compress::Deflate::Reader` and `Writer`; `src/compress/deflate/lib_z/`
  holds the zlib ones, and `reader.cr` and `writer.cr` pick one at compile
  time. `Compress::Gzip`, `Compress::Zlib` and `Compress::Zip` are built on
  those two classes and the checksums, so they change in no other way.
- `Digest::CRC32` and `Digest::Adler32` call Mica's checksums (CRC-32 with
  the ARMv8 CRC instructions on Apple Silicon); `combine` follows zlib's
  method.
- A program built with `-Duse_libz` compiles nothing in
  `src/crystal/mica/deflate/`.

## Evidence

Mica's `docs/deflate.md` holds the decoder's conformance, fuzz and speed
evidence. For this change (M4 Mac mini, macOS):

- `spec/std/compress`, `spec/std/digest`, `spec/std/http` and
  `spec/std/uuid_spec.cr`: 967 examples, 0 failures on Mica and on
  `-Duse_libz`.
- A differential run of 100,000 cases (seed 20261123): Mica's writers at
  every level, with flushes, read back by zlib's `inflate`; zlib's output at
  every level and strategy read by the standard library on Mica, with the
  bytes after a raw or zlib stream left in the source; checksums and
  `combine` against zlib's; and 100,000 mutated streams, whose outcome
  (output or rejection) is byte-for-byte the same as the standard
  library's on `-Duse_libz`.
