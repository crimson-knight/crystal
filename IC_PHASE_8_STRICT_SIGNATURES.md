# Phase 8: Fast Rebuilds and Strict Signatures

## Objective

Make the edit-compile loop fast without making Crystal a different language.
Two parts: remove the fixed costs every rebuild paid (step 0), and add an
opt-in language mode that makes a method body change local to that method
(step 1), the precondition for re-typing only what changed (step 3, not done).

Reference project: `~/apps/archive/crysterr` (Amber 2 + Grant + Slang + ECR +
i18n, ~8k lines of own code, 13 shards).

## Step 1: Strict signatures (`--strict-signatures`, `CRYSTAL_STRICT_SIGNATURES=1`)

Applies to the code under the current directory, except `lib/`. The standard
library and shards are untouched: they aren't edited, so they don't need it.

- **R1, return type firewall.** A declared return type is the type callers
  see, not the (possibly narrower) type of the body. `def foo : Int32 | String;
  1; end` makes `foo` an `Int32 | String`. Without this a body edit can change
  types anywhere in the program. Exceptions, where the body's type is kept:
  `NoReturn` bodies, restrictions that aren't value types (a generic without
  type arguments like `: Array`, a module, including `self` in a module).
  Implemented in `Def#map_type` (`semantic/bindings.cr`).
- **R2, return types are required** for every `def` in strict code, except
  `initialize`/`finalize` and methods generated by macros (they change only
  when the macro call does, which is a structural change anyway). Reported all
  at once after the top-level pass.

Instance variables don't need explicit declarations: a body edit that changes
a guessed ivar type can be detected cheaply in step 3 (compare the type
declaration results), so requiring them would only add migration work.

Annotated code stays valid Crystal: it compiles with an upstream compiler.

### `crystal tool annotate`

Compiles the program, takes the types of each method's instantiations and
writes them as return types. Prefers a concrete type, uses `self` and type
parameters (`T`, `Array(T)`) where the type follows the owner, and lists what
needs a human: methods never called, abstract methods, duck-typed helpers whose
type depends on the arguments (`def ident(x); x; end` wants `forall T`), and
generic methods used with a single instantiation (`Int32` vs `T` is ambiguous).
`--dry-run` prints instead of writing.

crysterr migration: 186 methods annotated by the tool, 12 by hand (+9 in
specs), and one existing declaration made precise (`to_db(Time) : DB::Any` →
`: String`, since callers now see the declared type). 115/115 specs pass both
with `--strict-signatures` and with the stock compiler.

## Not done: step 3

Strict mode alone doesn't make rebuilds faster. The payoff is a resident
compiler (`crystal watch`) that keeps the `Program`, re-types only the changed
method's instantiations when the change is body-only (Phase 6 signatures),
regenerates only their LLVM modules and relinks. Estimated 2-3 months.
